# Task 007 Controls Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Rebuild every standard button, field, choice and native select against the approved Figma control system, preserve behaviour, and deliver the result as one verified PR.

**Architecture:** Define the control vocabulary once as Tailwind `@utility` rules in `apps/web/src/theme.css`, lock its measurable design contract in `apps/web/src/tokens.test.ts`, then migrate existing native controls without introducing shared React wrappers. Keep specialised toolbar, table-rail, tab and menu controls specialised where their interaction model already requires it.

**Tech Stack:** React, TypeScript, Tailwind CSS v4, Bun test, dprint, oxlint, Playwright.

---

## Interface contract

- `btn` is the shared behavioural/typographic base.
- `btn-sm`, `btn-md` and `btn-icon` are the only sizes: 24px, 32px and a 28px square.
- `btn-primary`, `btn-secondary`, `btn-ghost` and `btn-destructive` are the only standard tiers.
- `field` owns the standard field edge, disabled state and invalid state.
- `field-ghost` is the transparent-at-rest native-select treatment.
- `choice-control` continues to style native checkbox and radio inputs.
- Consumers retain their existing layout classes, event handlers, state and accessible names.

The exact new palette values are:

```css
--color-brand-active: oklch(0.37546 0.06382 210.435); /* #034a54 */
--color-destructive-hover: oklch(0.56972 0.16045 24.136); /* #c44746 */
--color-destructive-active: oklch(0.53376 0.1489 24.091); /* #b34140 */
```
